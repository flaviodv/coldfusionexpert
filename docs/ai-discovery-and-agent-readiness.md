# SEO, AI Discovery and Agent Readiness

## Implemented

- [x] Clean, language-specific canonical URLs and reciprocal `hreflang` values are resolved centrally in `Application.cfc`.
- [x] Public pages provide title, description, canonical URL, robots directive, Open Graph, and Twitter card metadata through the shared headers.
- [x] Page-specific JSON-LD is generated by `cfc/SiteSchema.cfc`. The homepage uses `WebSite`, `Organization`, `Person`, and `ProfessionalService`; the profile uses `ProfilePage`; the ColdFusion service page uses `Service` and `FAQPage`; the tools landing page uses `CollectionPage`; tool pages retain `WebApplication` and `BreadcrumbList`.
- [x] `/llms.txt` offers a compact, non-authoritative discovery map for language models.
- [x] `robots.txt` allows public discovery while excluding source components, vendored files, and internal tool proxy endpoints. The two proxy endpoints also emit `X-Robots-Tag: noindex, nofollow, noarchive`.
- [x] The remote metadata fetcher does not automatically follow redirects, avoiding an unchecked redirect path to private network addresses.
- [x] A public 404 template is configured in `web.config`; it is noindexed.
- [x] The XML sitemap lists clean, bilingual public URLs. Keep it synchronized with built tools.

## Maintaining metadata and schemas

1. Add a top-level public page in the URL mapping section of `Application.cfc` with its title, description, canonical and alternate-language URLs.
2. Add a matching page kind to `cfc/SiteSchema.cfc` only when a specific Schema.org type accurately represents visible page content. Do not add review, rating, pricing, client, or result claims without visible, verifiable source material.
3. For a new tool, update `tools/_tools-registry.cfm`; the tool metadata produces its title, canonical, WebApplication schema and breadcrumb. Add its two language URLs to `sitemap.xml` only after it is marked `built: true`.
4. Update `llms.txt` when a primary public section changes. It is an aid, not a replacement for HTML, links, or the sitemap.

## Crawler policy

`robots.txt` is a traffic preference, not a security boundary. Protect sensitive content with authentication and ensure it is not deployed publicly. Specific AI crawler groups repeat the same exclusions as the wildcard group because crawler-specific rules take precedence. Review crawler names periodically against vendor documentation before changing the policy.

Public content is allowed for Google, OpenAI, Anthropic, Perplexity, and other compliant crawlers. No user agent is allowed to crawl `/cfc/`, `/vendor/`, `Application.cfc`, `tools-api.cfm`, or `tools-proxy.cfm`.

## Agent-ready boundary

Today the site exposes public, read-only HTML and browser tools only. It deliberately does **not** expose a generic public API or MCP server: the current tool endpoints proxy remote-page inspection and are unsuitable as a public data contract.

If a future integration is justified, expose a versioned, read-only catalog first (for example services, tools, and selected portfolio data) assembled from approved metadata rather than directly from a database. Give it explicit CORS, caching, input validation, rate limits, logging, and no secrets or administrative data. Any future contact, quote, or message action must be authenticated where appropriate, validated server-side, rate-limited, protected against abuse, and require clear user intent. Evaluate MCP only after those resources/actions and their authorization model are defined.

## Manual verification

1. Visit `/`, `/es/`, `/coldfusion-development`, `/es/coldfusion-development`, `/flavio-di-virgilio`, `/tools`, and one built tool in each language.
2. Inspect the rendered `<head>` for a single title, description, canonical, alternate links and one JSON-LD block appropriate to the page.
3. Confirm `/robots.txt`, `/sitemap.xml`, `/llms.txt`, and a nonexistent URL all return as expected; the nonexistent URL must retain HTTP 404.
4. Validate rendered JSON-LD with a structured-data validator and test redirects from old `.cfm` URLs after deployment.
5. Check server logs for unexpected crawl pressure or blocked legitimate bots. Verify crawlers by vendor-published methods rather than trusting the `User-Agent` string alone.
